店舗用LINEミニアプリ企画書

目的
顧客の再購入の促進

ユーザー機能
①ホーム画面　Blog機能（仮）
　ミニアプリホーム画面に表示
　投稿するとアプリ通知
②会員証
　会員証となるQRコード、会員ランク、利用可能ポイントの表示
③新規登録クーポン付与、使用
　何らかの方法でアプリユーザーは専用の友達登録リンク（仮）を発行できる。
　そのリンクから友達登録した場合、登録ユーザーにクーポンが付与
　登録ユーザーがクーポンを使って購入を完了した場合に、
　招待ユーザーにポイント付与
　
　遷移
　所持クーポン一覧→クーポン詳細画面
　↓
　友達招待ページ→リンク発行→招待リンク→ミニアプリ→招待コード保存→友達追加→登録→クーポン付与（取得したクーポンには、招待ユーザーの会員番号が付与されている）
④各種履歴の確認
　購入履歴の確認（購入日時、購入商品の金額（税込）、使用されたポイント額、使用されたクーポン、該当購入で付与されたポイント額）
　ポイント付与履歴と一覧表示
　
管理者機能
①ホーム画面
②ブログ投稿
③QR読み取り、決済処理
　読み取り後、決済情報入力
　購入店舗、購入金額（税込）、ポイント利用額、利用クーポン（利用可能なクーポンがあれば表示）
　情報入力後、決済処理
　１．購入履歴追加処理
　２．ポイント使用時はポイント使用処理
　３．ポイント付与処理（税込価格を参照し付与　最終購入から年でポイント失効　ポイント失効前1か月にアプリ通知）
　　　ポイントが付与されるのは３日後（７２時間後）
　　　商品購入時に担当者が管理者アカウントから顧客のアカウントにポイント付与
　　　会員ランクが上昇するほどポイント上昇率情報会員ランク（レギュラー（５％）→ゴールド（８％）→プラチナ（１０％））
　　　（年間購入額で会員ランクアップ（即時ランクアップ）　
　　　ランクが上がった場合次の決済から有効
　　　会員ランクは翌年の１２月３１日まで有効
　　　例：
　　　　　顧客A　2024年3月5日に会員ランクゴールドにアップ　この場合翌年2025年12月31日まで有効　2026年1月1日にランクリセット
　　　　　　　　 2025年内のランクポイント（仮）は2025年内の購入情報でたまり、この結果に応じて2026年の会員ランクが決まる
　　　　　　　　 尚、年度内の総合ランクポイントが前年度を超え、来年反映予定の会員ランクが現在の会員ランクが上回った場合は、
　　　　　　　　 当年度にも会員ランクが反映される
　　　）
　４．クーポン利用時は、該当クーポン利用処理
　　　クーポンが利用済み状態になる
　　　利用されたのが友達紹介クーポンだった場合、
　　　該当クーポンに付与されている会員番号の会員に、７日後にポイントが付与される
④決済履歴、決済取り消し（会員番号で絞り込み可能）
　決済をキャンセル可能
　キャンセルされた決済はキャンセル状態となる
　使用されたポイントがその分付与
　クーポンを使用していた場合はクーポンの利用済み状態を解除
　該当決済でのポイントの付与を取り消し（利用可能ポイントから減額）
　付与前だった場合は付与がキャンセルされる
　友達紹介クーポンによるポイント取り消しが予定されていた場合、それもキャンセル
　既にポイントが付与されていた場合は仕方ない（！？）
　ただし、該当会員の最終購入のみがキャンセル可能

管理者アプリのLIFF設定について

管理者機能（/admin 配下）はユーザー向けとは別のLIFFアプリとして登録する。
フロントエンドのコードは同一だが、LINEデベロッパーコンソール上で2つのLIFFアプリを登録し、
アクセス元のLIFF IDをバックエンドで判別することで管理者権限を付与する。

【設定手順】

１．LINE Developersコンソール（https://developers.line.biz/）にログイン

２．対象チャネル（LINE Loginチャネル）を開き、「LIFF」タブから2つのLIFFアプリを登録する

　ユーザー用LIFF
　　名前         : （例）店舗アプリ
　　サイズ       : Full
　　エンドポイントURL : https://{フロントエンドのドメイン}/
　　Scope        : profile, openid
　　ボットリンク機能 : On（Aggressive）

　管理者用LIFF
　　名前         : （例）店舗アプリ（スタッフ用）
　　サイズ       : Full
　　エンドポイントURL : https://{フロントエンドのドメイン}/admin
　　Scope        : profile, openid
　　ボットリンク機能 : Off
　　※ミニアプリとして審査・公開申請は行わない（URLを知るスタッフのみアクセス可能）

３．発行された2つのLIFF IDをバックエンドの環境変数に設定する
　　LIFF_ID_USER=xxxx-xxxxxxxxx
　　LIFF_ID_ADMIN=yyyy-yyyyyyyyy

４．バックエンドはLINEアクセストークン検証時にLIFF IDを確認し、
　　LIFF_ID_ADMINからのアクセスであれば管理者ロールを付与する

５．管理者用LIFFのURLをスタッフにのみ共有する（リッチメニュー等には掲載しない）
　　URL形式 : https://liff.line.me/{LIFF_ID_ADMIN}

【スタッフ変更時の対応】
　退職等でアクセスを無効化したい場合は、LINEデベロッパーコンソールで
　管理者用LIFFのエンドポイントURLを変更するか、LIFFアプリを再作成してURLを再発行する。
　新しいURLをスタッフに共有し直すことで、旧URLは無効となる。
